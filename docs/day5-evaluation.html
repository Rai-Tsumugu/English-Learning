🗣️ 個別評価議事録

🎯 マーケター — 7/10

強み

  • 「個人用・低コスト・自律生成・統合型」は未開拓セグメント、商用と機能戦争にならない
  • JSON Schema強制＋10%サンプリングReviewはハルシネーション対策の正解パターン
  • 巨大CTA・前夜事前生成・リカバリーチケットがストリーク依存を補完

弱み

  • 「英語の地力」未定義（§1.1）。スピーキング/発音スコープ外が明文化されておらずKPI軸ぶれ
  • 差別化の核（ネットマップ）がPhase3で価値検証できない
  • $5上限はキャッシュ60%が前提。未達時のフォールバックが弱い

改訂提案

  • §1.1 を「読む・語彙・文法の地力」と明記、スピーキング/発音は§1.2 非目標へ
  • §1.4 Phase1に「簡易ネットマップ（関連語5件リスト）」を前倒し
  • §8 にキャッシュ未達時の段階的縮退表（Review停止→静的教材→生成停止）追加

🏗️ プログラマ — 8/10

強み

  • Qdrant廃止 + sqlite-vec採用は個人用localhost規模に合致
  • Curriculum→Generator→Review直列 + JSON Schema強制は Responses API + Structured Outputs で素直に実装可能
  • Dev=Compose / 常用=単一バイナリ のハイブリッド方針が静的Goと整合

弱み

  • sqlite-vec が alphaであること・KNN制約・Goバインディング選定が未記載
  • SSE実装の必須要件（Flusher・heartbeat・X-Accel-Buffering）未記述
  • プレースメント20問の動的生成は捏造idiom混入で初期プロファイルが歪む

改訂提案

  • §2 に「sqlite-vec 0.1.7-alpha / Goドライバ=modernc.org/sqlite+modernc.org/sqlite/vec」明記、§11残課題に alpha 監視追加
  • §3.1 に internal/sse パッケージで plan/question/done 3イベントへ正規化を追記
  • §4.1 を「静的問題バンク（人手レビュー済み）使用、動的生成しない」に改訂。§4.3 Review表に 10%→20%→40%自動昇格サーキット追加

📚 英語講師 — 6/10 ⚠️ 最低スコア

強み

  • SM-2採用は実証十分・実装容易（Wozniak長期試験で保持92%）
  • NGSL + sqlite-vec は頻度上位語の定着基盤として教育学的に正解
  • 前夜バッチ生成 + 巨大CTA はモバイル学習研究の知見と一致

弱み

  • 意味的近接語の同時導入リスク: 関連語を新規出題に使うと Tinkham 干渉効果（学習試行+50%）
  • コロケーション・音韻面の欠落（日本人EFL主要弱点）。Phase2長文だけでは頭打ち
  • CEFR進捗の不可視。週30語KPIあるが「目標CEFRまでの残語数」がなく年単位の現実感ゼロ

改訂提案

  • Curriculum Agent に distinctiveness optimizer 明記。ネットマップは復習・可視化専用に限定
  • examples.collocation 列追加、Generator に高頻度コロケート2つ必須出力。1日1文 TTS シャドウイング枠を残課題から昇格
  • ダッシュボードに「累積分/週」「現在語彙→目標CEFR残語数」表示。lapse時 ease 下限1.3、1日新規語上限10–15を明記

📦 OSSデータアナリスト — 7/10

強み

  • gpt-4o-mini + sqlite-vec + キャッシュ60% で $5/月 の現実性高い
  • SRS + JSON Schema + Reviewサンプリング で品質と継続性が両立
  • Phase分割が明快、Phase1 2週間スコープが妥当

弱み

  • §4.2 が「NGSL/COCA取り込み」と記載しており COCA再配布不可リスク を内包
  • words/examples に source/attribution 列がなく出典追跡不能
  • 例文最低3保証のシード（Tatoeba/Tanaka）と不足時の Generator 委譲ロジック未定義

改訂提案

  • §4.2 「COCA」→「CEFR-J + Octanove C1/C2」に置換、COCAは頻度参照のみと明記
  • §5 に words.source, examples.source, examples.attribution 追加。CC BY-SA 伝播回避のため vocab.db/app.db 分離
  • §2/§10 に data/sources/LICENSES/ 同梱と起動時ライセンス整合性チェック追加

🎨 UXリサーチャー — 7/10

強み

  • 巨大CTA + 前夜バッチで「朝ゼロ待機」、即時性原則に合致
  • リカバリーチケットで all-or-nothing 離脱を抑制
  • SRS + 苦手重み付け + ネットマップ点灯で達成感の即時化素地

弱み

  • ストリーク表示形式が未定義。連続日数カウンタだと1日途切れで全放棄リスク
  • 過負荷サーキットブレーカー記述なし（Anki 50枚問題と同型破綻リスク）
  • 通知/ambient cue 戦略 docs 欠落、起動導線がユーザー意思のみに依存
  • Dogfooding 盲点を検知する仕組み未設計

改訂提案

  • §4.6 に「週7マス可視化」「月2枚自動付与チケット」「正解時マイクロ報酬（点灯+音+次回日表示）」明記
  • SRS未消化3日分超で新規語投入自動停止を Curriculum 制約に追加
  • macOS launchd ambient cue + 週次レポート「詰まった瞬間」自由記述欄を運用要件化

🤖 AIエンジニア — 8/10

強み

  • JSON Schema強制 + 再試行2回 は Structured Outputs 99.9%準拠と整合
  • 3エージェント分業 + 10%サンプリングReview のコスト/品質バランスが妥当
  • 生成キャッシュ(hash) + 前夜23時バッチ は Batch API(50%OFF) + プロンプトキャッシュで月予算1桁圧縮余地

弱み

  • Reviewer self-bias: Generator/Reviewerが同一 gpt-4o-mini だと style bias 0.76-0.92 で検出力低下
  • CEFR 厳密制御の few-shot 固定方針が未記載、難易度ブレ発生
  • 読解の正答根拠検証（answer_span 照合）が設計欠落

改訂提案

  • Reviewer を別系統化（gpt-4o or 別プロンプト + ルーブリック4段階 + 理由必須）。新形式初出時は100%レビュー
  • Batch API + プロンプトキャッシュを正式採用、共通プレフィックス固定で月 $1 以下に再設定、浮いた予算を Review 強化へ
  • Generator 出力に answer_span/cefr_evidence 必須化、Review で機械照合

🧪 学習科学研究者 — 7/10

強み

  • Testing Effect ◎: 4択+latency記録+Review解説が想起練習に合致（g≈0.5–0.6）
  • Elaboration ◎: 例文3つ・ネットマップ近傍語・ツールチップ訳が深い意味処理を誘導
  • autonomy 配慮: リカバリーチケットが SDT undermining effect を緩和

弱み

  • SRS が SM-2: FSRS-5 比で同保持率にレビュー20–30%増、ease hell 残存
  • CAT の較正欠落: IRTパラメータ・SEM停止規準・自己申告統合方針未定義
  • Interleaving / semantic interference 未制御。Curriculum に混在制約なし、近傍語同時出題で30–50%効率低下リスク

改訂提案

  • attempts に stability/difficulty/lapses 列を先行追加し Phase2 で FSRS-5 移行可能化、desired retention を profile 化
  • Curriculum プロンプトに「品詞/意味カテゴリ/CEFR 混在」「類義語同時出題禁止」制約。A1–A2は初回blocked→2回目interleaved のハイブリッド
  • CAT を IRT 化: 項目バンクに a/b パラメータ事前付与、SEM≤0.3 or 20問の二重停止規準、CEFR自己申告をベイズ事前分布として活用。産出型タスク（タイピング/和→英）一部混在

✅ Day5 最終結論

目標達成可能性: 条件付きGo (7.14 / 10)

個人用localhost英語学習サイトとして、Phase1の2週間稼働・月$5予算・週6/7継続KPI は 技術・コスト・市場の3軸で達成可能。一方で「英語の地力」獲得の質を高めるには以下7改訂を v0.3 に取り込むことが必須・推奨される。

必須改訂（最低限 Phase1 着手前）

  1. §1.1 目的を「読む・語彙・文法」に限定、スピーキング/発音を §1.2 非目標へ（マーケター）
  2. Curriculum に類義語同時出題禁止 / 意味カテゴリ混在制約を明記（英語講師・学習科学）
  3. プレースメントを静的問題バンク化、動的生成を禁止（プログラマ）
  4. COCA記載削除＋source/attribution 列追加、vocab.db / app.db 分離（OSSデータ）

強推奨改訂（Phase1 内に追加）

  1. Reviewer を別モデル系統化（gpt-4o 等）＋ answer_span 必須化（AIエンジニア）
  2. attempts に stability/difficulty/lapses 列を先行追加し Phase2 で FSRS-5 移行可能化（学習科学）
  3. §4.6 UX 詳細化: 週7マス可視化・月2枚自動チケット・SRS未消化3日で新規停止・launchd ambient cue（UX）

Phase1 着手後の伸びしろ

  • Batch API + プロンプトキャッシュで月予算を $1 以下に圧縮 → Review 拡張原資に転用
  • コロケーション必須化＋TTS シャドウイング枠（残課題から昇格）
  • ダッシュボードに「目標CEFRまでの残語数」表示
  • 週次レポートに「詰まった瞬間」自由記述欄（dogfooding 盲点検知）
