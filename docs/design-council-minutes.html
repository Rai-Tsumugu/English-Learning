🔁 Round 1 議事録 — 初版 v0.1 評価

平均: 6.24 / 10 → 不合格、改訂へ

🎯 PM (7.2)

良い点

  • Non-Goals 明示でスコープが個人用localhostに整合
  • 3エージェント分割 (Curriculum/Generator/Review) の品質ゲート設計
  • 継続支援 (ストリーク・5分ノルマ) がKPI核に直結

問題点

  • 高 MVPスコープが未定義、優先度・フェーズ分けがない
  • 高 成功指標 (KPI) が皆無、「地力UP」が測定不能
  • 高 コールドスタート時の現在地取得が未設計
  • 中 コスト上限の具体値なし、キャッシュ戦略なし
  • 中 SRS (間隔反復) への言及なし

🏗️ アーキテクト (5.5)

良い点

  • レイヤ分離が素直で実装着手しやすい
  • 3エージェント分割の責務が直交
  • 個人用localhostスコープが過大化していない

問題点

  • 高 API設計が完全に欠落
  • 高 エージェントオーケストレーション (順序・リトライ・JSON Schema強制) 未定義
  • 高 データフロー図がない
  • 高 テスト戦略が章ごと欠落
  • 中 Qdrant採用過剰 (sqlite-vec で十分)
  • 中 SQLiteのWAL/マイグレーション/バックアップ未記載

🔒 セキュリティ (5.5)

良い点

  • 非目標明記で攻撃面が限定的
  • ローカルSQLite + Docker Composeで外部露出最小
  • ReviewAgentが品質ゲートの素地

問題点

  • 高 APIキー管理 (.env/secrets/ログマスキング) 未定義
  • 高 プロンプトインジェクション対策の欠如
  • 高 Docker設定の安全性 (ポートバインド/CORS/非root) 未記載
  • 中 学習履歴データ保護・OpenAI送信範囲未定義
  • 中 コスト/レート制御 (鍵漏洩時の被害上限) なし

🎨 UX (6.5)

良い点

  • ストリーク + 5分ノルマで継続ハードルを低設定
  • 未習得語の自動ツールチップ訳がフリクション低減
  • ReviewAgentで生成物信頼性をUX側で担保

問題点

  • 高 継続動機の設計が薄い (途切れ復帰・達成感の欠落)
  • 高 学習開始導線とオンボーディング未定義
  • 中 生成遅延 (2〜10秒) のUX未考慮
  • 中 日本語サポートの粒度・切替UI未設計

📊 ビジネス (6.5)

良い点

  • 非目標明示でスコープ収束
  • gpt-4o-mini + text-embedding-3-small の低コストモデル選定
  • 継続支援機能がROIに直結

問題点

  • 高 コスト試算が皆無、3段エージェントは容易に浪費
  • 高 Qdrant+Compose 構成は個人用としてオーバーエンジニアリング
  • 中 MVP優先順位が未定義
  • 中 生成物キャッシュ戦略なし

🛠️ Round 1 → 2 改訂アクション (アーキテクト統合)

  • §1.3 KPI追加: 週次継続率 ≥6/7、週30語、月$5
  • §1.4 MVP 3 Phase分割: Phase1=クイズ+ストリーク / Phase2=長文+日本語3モード / Phase3=マップ可視化
  • §2 技術スタック: Qdrant廃止 → sqlite-vec、goose導入
  • §3.1 シーケンス図: Curriculum→Generator→Review→キャッシュ→SSE返却
  • §4.1 オンボーディング: CEFR自己申告 + 20問プレースメント
  • §4.3 エージェント仕様表: 入出力・失敗時挙動・JSON Schema強制・10%サンプリングReview
  • §4.4 SRS (SM-2) 導入、attempts に next_review_at, ease_factor 追加
  • §4.6 UX継続: 巨大CTA、前夜バッチ事前生成、リカバリーチケット
  • §5 データモデル拡張: users(単一行), generated_content, word_vec, tokens_used
  • §6 API一覧: 6エンドポイント + RFC 7807エラー形式
  • §7 セキュリティ章新設: シークレット/ポート/非root/暗号化BK/インジェクション対策/usage limit
  • §8 コスト試算: 日30k tokens, 月$5 hard limit, キャッシュ60%目標
  • §9 テスト戦略: Go test / ゴールデン / LLM-as-judge / Playwright
  • §10 運用: sqlite .backup + age暗号化, goose自動適用, JSON構造化ログ

🔁 Round 2 議事録 — 改訂版 v0.2 評価

平均: 9.20 / 10 → 合格

🎯 PM (9.2 ✅)

評価: MVP分割が明確化し2週間で稼働可能なスコープに収束。KPI定量化とコスト試算が整合。コールドスタート＆SRS導入でパーソナライズの欠落ピースが埋まった。

残課題: KPI未達時のフィードバックループ、Phase移行条件、TTS判断基準の明示。

🏗️ アーキテクト (9.2 ✅)

評価: Qdrant→sqlite-vec で依存削減・単一バイナリ運用可。エージェントI/Oが実装可能粒度。API一覧・テスト戦略・コスト試算が揃い設計の穴がほぼ埋まった。

残課題: SSE再接続/resume token、generated_content.hash の生成元定義、SM-2初期値とdifficulty_profile JSON Schema、observability。

🔒 セキュリティ (9.2 ✅)

評価: §7独立章でシークレット/ポート/コンテナ/データ保護/インジェクション/コスト/依存管理が体系化。鍵漏洩時の被害上限あり。

残課題: SSE/CORS Origin検証、ユーザー入力含む生成は100%レビュー、hash定義に schema_ver/model 追加、age鍵管理場所。

🎨 UX (9.2 ✅)

評価: オンボーディングで初日からパーソナライズ起動、前夜バッチ+SSEでゼロ待機、日本語3モード+リカバリーチケットで継続動機が多層化。

残課題: Phase1の即時報酬演出、SSE中のプレースホルダ表現、20問プレースメントの中断再開、リカバリーチケット上限設計。

📊 ビジネス (9.2 ✅)

評価: KPI＋月$5 hard limit でROI測定可能、キャッシュ60%＋日次上限でコスト暴走を構造的に防止。

残課題: Phase2/3着手のGate条件、コーパス取り込みの初回コスト計上、ネットマップ可視化のROI再評価条件。

✅ 最終結論

主要決定事項

  • MVPはPhase1のみを2週間で実装着手 — クイズ + ストリーク + 履歴 + オンボーディング
  • 技術スタック確定: Go (chi) + React (Vite+TS) + SQLite + sqlite-vec + OpenAI gpt-4o-mini
  • コスト上限: 月 $5 hard limit、日次30k tokens、キャッシュヒット率60%目標
  • セキュリティ: 127.0.0.1限定バインド、非rootコンテナ、JSON Schema+タグ分離でインジェクション防御、age暗号化BK
  • パーソナライズ: SM-2 SRS + 20問プレースメントで Day1 から起動
  • 継続UX: 巨大CTA + 前夜バッチ生成 + リカバリーチケット

残課題 (Phase1着手と並行して詰める)

  • SSEイベントスキーマ・resume token 仕様化
  • generated_content.hash = sha256(model || schema_ver || prompt_inputs) と prompt_version 列追加
  • CORS allowlist (http://127.0.0.1:5173) と Origin/Referer 検証
  • 各Phase移行Gate条件 (例: 週6日継続×2週連続 → Phase2)
  • Phase1での即時報酬マイクロ演出 (語点灯/+XP)
  • observability: トークン日次・キャッシュヒット率・p95レイテンシのログ規定
